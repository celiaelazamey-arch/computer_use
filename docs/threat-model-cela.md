# نموذج التهديد: cela.sh

**الحالة:** وصف الوضع الحالي في الإصدار 1.0.2، بما في ذلك إعداد API السحابي أحادي المشغّل والفجوات المتبقية.

**النطاق:** مكوّن Python المحلي/السحابي `src/cela_sh/`. نموذج `ccelia2027/` منفصل في `ccelia2027/docs/threat-model.md`، لأن `CONTRIBUTING.md` يشترط نموذجين منفصلين.

## الأصول

- نص الهدف والسياق (`--goal`, `--context`)، وملاحظات `learn`، والمحتوى المستخرج من ملفات `learn-file`: بيانات المستخدم.
- الذكريات المخزنة في SQLite أو Qdrant عند تفعيل الذاكرة، ونسخها الاحتياطية.
- مفتاح Qdrant API (`CELA_QDRANT_API_KEY`) عند استخدام Qdrant بعيد.
- مفتاح API المشترك (`CELA_API_KEY`) عند تفعيل Bearer auth أو النشر عبر overlay السحابي.
- الخطة الناتجة: نصيحة فقط، لا تنفيذ. لكن أي مستهلك لاحق قد يتصرف بها.

## الفاعلون والثقة

| الفاعل                        | مستوى الثقة  | ملاحظة                                                     |
| ----------------------------- | ------------ | ---------------------------------------------------------- |
| المشغّل المحلي (CLI / Python) | موثوق        | يملك الجهاز والبيئة؛ كتابة `learn` تتطلب نصًا يمرره صراحةً |
| عميل API بعيد                 | غير موثوق    | لا يُسمح له بمسارات التخطيط/الذاكرة إلا برمز Bearer مضبوط  |
| نص الهدف والسياق              | غير موثوق    | يُعامل كبيانات، لا كتعليمات                                |
| الذكريات المسترجعة            | غير موثوقة   | محتوى تاريخي قد يكون مسمّماً                               |
| مخرجات النموذج (Ollama)       | غير موثوقة   | تمر عبر تحقق صارم ثم سياسة حتمية                           |
| Qdrant                        | موثوق جزئياً | محلي افتراضياً؛ البعيد يتطلب HTTPS ومفتاحاً                |

## حدود الثقة

1. **CLI ← البيئة:** الإعداد من متغيرات العملية فقط، ولا يُحمَّل `.env` تلقائياً.
2. **Python → Ollama:** HTTP على loopback افتراضيًا؛ استثناء `CELA_ALLOW_OLLAMA_CONTAINER_HOST=true` يسمح باسم `ollama` فقط داخل شبكة Docker موثوقة. رفض إعادة التوجيه وتعطيل البروكسيات (`trust_env=False`) باقيان.
3. **Python → Qdrant:** loopback HTTP، أو HTTPS مع مفتاح API للعناوين البعيدة. ترفض الإعادة.
4. **النموذج → المخطط:** `RawPlan` بـ `extra=forbid` وأنواع صارمة، ثم `apply_policy`.
5. **الخطة → المستهلك:** JSON مع `dry_run=true` و`execution_enabled=false` مقفولين على مستوى النوع (`Literal`).
6. **HTTP → API المحلية/السحابية:** المصادقة اختيارية محليًا؛ عند `CELA_API_KEY` تتطلب `/plan` ومسارا الذاكرة Bearer token، ويجعل overlay السحابي المفتاح إلزاميًا. `/health` والتوثيق عامّان، ومنافذ Compose محصورة على host loopback خلف TLS ingress. المفتاح مشترك لمشغّل واحد؛ لا يحوّل معرّف الجلسة إلى هوية.
7. **Python → SQLite/vec0:** امتداد C رسمي مثبت الإصدار، يحمّل من الحزمة ثم يعطّل تحميل الامتدادات. النص والمتجه يكتبان في معاملة واحدة، والبحث يرشح scope session قبل top-k ثم يتحقق منها عند ربط النص.
8. **مشغّل → الذاكرة:** `learn` و`learn-file` و`POST /memory` طلبات كتابة صريحة. يسجل التطبيق النوع والوسوم والنطاق، ويخزن النص والتضمين؛ لا يغير أوزان النموذج.
9. **CLI → ملف محلي:** `learn-file` يقرأ ملفًا واحدًا من `.md` أو `.txt` أو PDF دون اتصال شبكي، بحدود للحجم والصفحات والنص المستخرج. تحفظ هوية المصدر مسارًا نسبيًا آمنًا وبصمتي الملف/المقطع؛ المسار نفسه يستبدل نسخته السابقة، مع عدم الاحتفاظ بتاريخها. تحليل PDF يستخدم الإضافة الاختيارية `pypdf`.

## خارج النطاق

- تنفيذ الخطط على الجهاز. غير موجود، وأي إضافة له تحتاج نموذج تهديد جديداً.
- أمن Ollama أو Qdrant نفسيهما، وتحديثهما.
- حماية الجهاز المحلي من برمجيات أخرى تعمل عليه.

## شروط إعادة فتح هذا النموذج

يجب تحديث هذه الوثيقة قبل أي من التالي:

1. إضافة أي فعل يُنفَّذ، أو أي اتصال خارج loopback وشبكة Docker الموثوقة الموثقة هنا، أو توسيع الاستثناء إلى اسم آخر.
2. إضافة مزود نموذج خارجي (سحابي أو API)، لأن النص سيخرج من الجهاز.
3. مشاركة بيانات أو أسرار مع `ccelia2027/`.
4. تغيير `session_id` إلى مصادقة حقيقية، أو تفعيل الذاكرة افتراضيًا خارج إعداد الحاوية الصريح.
5. إتاحة API لمستخدمين غير موثوقين أو نشرها كخدمة مشتركة: هوية وتفويض لكل مستخدم، وعزل ملكية الذاكرة، وحدود معدل مطلوبة؛ المفتاح المشترك الحالي لا يحقق ذلك.

## معالجات مقترحة (لم تُنفَّذ)

- **F1/F2:** توسيع `SENSITIVE_TERMS` بالأفعال الإنجليزية والعربية المذكورة، مع اختبارات تفشل قبل الإصلاح. وإعادة تسمية `ready` في الوثائق إلى توضيح أنه "لا يحتاج تأكيداً حسب السياسة الحالية".
- **F4:** إضافة `pip-audit` إلى `check-all` وCI، كما تفعل Worker بـ `npm audit --audit-level=high`.
- **F3:** المفتاح المشترك مناسب لمشغّل واحد فقط؛ قبل أي خدمة مشتركة، اربط كل `session_id` بهوية موثقة وطبّق تفويضًا على القراءة والكتابة وحدود معدل.
